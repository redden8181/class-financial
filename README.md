# КлассКасса

PWA для ведения денежных сборов **одного школьного класса**. Дети, сборы, долги,
история оплат — всё в одном простом приложении, которое открывается ссылкой и
устанавливается на телефон прямо из браузера (без App Store и Google Play).

## Возможности

- **Дети**: добавление, редактирование, удаление, поиск; автоматические группы
  «Мальчики» / «Девочки».
- **Сборы**: любые категории (шторы, праздник, экскурсия…) — название, сумма
  с ребёнка, дата, необязательное описание.
- **Отметки оплаты**: «Сдал» / «Не сдал» одним нажатием, дата оплаты сохраняется
  автоматически. Массовая отметка «Все сдали».
- **Статистика по сбору**: всего детей, сдали, не сдали, собрано, осталось собрать,
  процент выполнения с прогресс-кольцом.
- **Карточка ребёнка**: вся история оплат, сумма оплаченного, общий долг.
- **Экран «Все долги»**: кто, за какие сборы и сколько должен + общая сумма долга.
- **Главная**: собрано всего, осталось собрать, количество должников, активные сборы.
- **Темы**: светлая и тёмная.
- **Офлайн**: приложение работает без интернета после первого открытия.

## Хранение данных

Все данные хранятся **локально на устройстве пользователя в IndexedDB**
(база `klasskassa`); бэкенда и регистрации нет. При первом запуске новой версии
данные из прежнего localStorage-хранилища автоматически мигрируют в IndexedDB.
Обновления приложения **никогда не удаляют** пользовательские данные.

## Запуск локально

```bash
npm install
npm run dev
# открыть http://localhost:3000
```

Сборка production-версии (обычный серверный режим):

```bash
npm run build
npm start
```

## Деплой на GitHub Pages

Проект полностью готов к публикации: достаточно загрузить код в репозиторий.

1. Создайте репозиторий на GitHub и отправьте код:

```bash
git init
git add .
git commit -m "КлассКасса: первая версия"
git branch -M main
git remote add origin https://github.com/<user>/<repo>.git
git push -u origin main
```

2. Откройте на GitHub: **Settings → Pages → Build and deployment → Source** и
   выберите **GitHub Actions**.

3. Workflow `.github/workflows/deploy.yml` при каждом `git push` в `main`:
   - устанавливает зависимости (`npm ci`);
   - собирает статический сайт (`next build` в режиме `output: export` → папка `out/`);
   - подставляет базовый путь `/<repo>/` (для репозитория вида `<user>.github.io` — корень);
   - проставляет новую версию в service worker;
   - публикует результат на GitHub Pages.

4. Откройте адрес `https://<user>.github.io/<repo>/` с телефона →
   **Поделиться → «На экран "Домой"»** (iOS) или **⋮ → «Установить приложение"**
   (Android). Приложение будет работать как обычное, в полноэкранном режиме.

> Локально проверить сборку для Pages можно так:
> `GITHUB_PAGES=true NEXT_PUBLIC_BASE_PATH=/<repo> npm run build` — результат в `out/`.

## Автообновление приложения

Схема из коробки решает проблему «пользователь видит старую версию»:

- HTML отдаётся по стратегии **network-first** — новая версия страницы приходит
  сразу при наличии сети; офлайн используется кэш.
- Файлы `/_next/static/…` и иконки — **cache-first** (имена с хэшем, неизменны).
- При каждой сборке `next.config.ts` генерирует `public/sw.js` из
  `scripts/sw.template.js`, подставляя уникальную версию
  (`<pkg.version>-<номер запуска Actions / SHA коммита>`). Новая версия —
  новые имена кэшей; при активации старые кэши удаляются.
- Клиент (`UpdateManager`) проверяет обновления каждую минуту, при возвращении
  во вкладку и на фокусе. Как только новый service worker установлен,
  приложение активирует его и мягко перезагружается (дождавшись видимости
  вкладки), показывая уведомление «Приложение обновлено».
- Очищать кэш браузера или переустанавливать PWA **не нужно**. Данные в
  IndexedDB при обновлении сохраняются полностью.

## Структура проекта

```
src/
  app/            # страницы (роуты): главная, дети, сборы, долги, формы
  components/     # UI-кит, навигация, диалоги, карточки списков
    forms/        # формы ребёнка и сбора
    pwa/          # UpdateManager — регистрация SW и автообновление
  lib/
    types.ts      # модели данных (Kid, FundCollection, PaymentsMap)
    db.ts         # IndexedDB-хранилище + миграция из localStorage
    store.ts      # состояние (zustand + persist) и действия
    stats.ts      # бизнес-логика: статистика, долги, итоги
    format.ts     # форматирование денег/дат/числительных
    demo.ts       # демонстрационные данные
    pwa.ts        # константы путей с учётом base path
scripts/
  sw.template.js  # шаблон service worker (версия проставляется при сборке)
.github/
  workflows/deploy.yml  # авто-сборка и деплой на GitHub Pages
```

Благодаря изоляции `lib/db.ts` + `lib/store.ts` следующий этап —
облачная синхронизация — добавляется заменой/расширением движка хранения,
без переписывания экранов.

## Замечания

- `.env` не коммитится (см. `.gitignore`) — приложению секреты не нужны.
- `public/sw.js` генерируется при сборке и тоже игнорируется git'ом.
